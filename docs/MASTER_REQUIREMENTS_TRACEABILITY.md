## C. Инварианты для реализации и приёмки

1. Не смешивать «аккаунт вошёл», «API доступен», «назначение выбрано» и «публикация готова».
2. Не отдавать UI сохранённые Client Secret, OAuth tokens, cookies или другие секреты.
3. Не выводить секреты и персональные данные в логи, analytics или долговременные lessons.
4. Не делать retry для `publish_unknown` до reconciliation с площадкой.
5. Собирать уроки на bounded, channel-scoped evidence; repeated scans не увеличивают sample без новых исходных строк.
6. Сбой чтения/записи одного источника должен быть изолирован и не удалять валидное доказательство из другого.
7. UI обязан отображать stale/error/unknown/empty отдельно.
8. Реальная публикация, production migration, массовый repair/import требуют отдельного approval и backup/preview.
9. Сохранять Windows/Linux parity; проверять build artifact, а не только Python tests.
10. Каждый следующий checkpoint привязывается к конкретному commit SHA и workflow run.
