## 4. Внешние блокеры и действия оператора

Эти пункты нельзя закрыть только изменением кода:

1. PR #60: требуется ревью и решение о включении его OAuth/UI изменений.
2. OAuth и live-доступы: нужны реальные app credentials и интерактивное согласие владельца аккаунта; CI не подтверждает доступ к площадке.
3. VK: для чтения метрик нужен пользовательский токен с соответствующим scope; групповой токен не является заменой.
4. Планировщик: живой режим исполнения плана, миграции и перезапуск действующего сервиса требуют отдельного окна обслуживания и проверки backup/schema. До этого live-исполнение плана не объявлять подтверждённым.
5. Исторические repair/import операции, способные менять много строк, выполнять только после свежего backup, read-only preview и отдельного согласия.
6. Для каждой площадки нужен владелец аккаунта, выбранное назначение и разрешение на контролируемую тестовую публикацию.

## 5. Правила приёмки

- Не публиковать в live без явного подтверждения.
- `publish_unknown` не повторять автоматически; сначала сверка с площадкой.
- Отсутствующая метрика ≠ ноль; неизвестный статус ≠ успех.
- Сохранённый токен/сессия ≠ доказательство API-доступа или права публикации.
- Правила Reddit/Pikabu/VC.ru перечитывать перед внешним действием; неизвестные или устаревшие правила блокируют отправку.
- Не добавлять второй backend, вторую очередь или второй источник истины, если уже есть подходящий контракт.
- UI должен различать fresh/stale/partial/empty/unavailable/unknown и сохранять последнюю успешную выборку при временной ошибке.
- Тестовые данные и offline demo не являются live-приёмкой.
