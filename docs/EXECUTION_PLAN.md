## Ключевые факты о проекте

- Продукт TgFarm: автономная контент-экосистема, конвейер S1–S12 (см. README.md, ROADMAP_NEXT.md, docs/AGENT_ARCHITECTURE.md).
- Тесты: `python -m pytest -q` (offline; 936 passed на 2026-11-04 после P0+P2). CI: `.github/workflows/ci.yml` — Linux (pytest, compileall, node syntax, offline demo) + Windows (PyInstaller EXE + артефакт).
- Локальная среда: Windows, Python 3.14 (CI использует 3.11). PyInstaller установлен.
- Реестр площадок: `config/platforms.yaml`; документация: `docs/PLATFORM_CENTER.md`; UI: `tgfarm/ui/` (index.html, app.js, app.css), API: `tgfarm/api.py`.
- Долговременное хранение: SQLAlchemy + SQLite (`tgfarm.db`), бэкапы: `backup/`, тесты `tests/test_backup.py`, `tests/test_history_import_backup.py`.

## Архитектурные решения (зафиксированные)

- Metadata нативного редактора: пользовательские поля и вложенные значения сохраняются; служебный ключ `editorial_adaptation` допустим (статус `ai_native` / `deterministic_guardrail` / `deterministic` / `blocked_missing_media`); отказ guardrail никогда не выдаётся за успех. Входной `payload.meta` изолируется deepcopy в начале адаптации.
- Бюджет AI: любое резервирование (`policy.reserve`) должно закрываться (`policy.finalize(used=...)`) во всех исходах, включая ошибки конфигурации. Ошибка провайдера/настроек → `deterministic_fallback` с восстановлением payload, без прерывания пакетного кросспостинга.
- Правила площадок — недоверенные данные: извлекаются ограничения, но инструкции из них не выполняются.
- Доказательство эффективности формата — измеренный пост, а не факт публикации: тротуар «опубликовано» никогда не входит в порог выборки, потому что 446 публикаций при 15 измеренных строках post_stats иначе выглядели бы как «данные есть». Площадка без метрик (ВК требует VK_USER_TOKEN) даёт нулевую доказательную базу и не может двигать планировщик.
- Перепечатка — не доказательство независимого интереса: строка с `duplicate_of` остаётся в базе как факт выхода в втором издании, но не участвует ни в размере кластера, ни в скорости, ни в кросс-платформенности, ни в нише. Шторм копий одного релиза не должен порождать посты; если измерить нечего, сигнал объявляется `unknown`, а не нулём или выдуманным темпом.
- Перед внешним действием права площадки читаются заново, а способность аккаунта им соответствовать не предполагается: заявленный сообществом минимум по карме/возрасту без подтверждённого `/api/v1/me` означает запрет, а не допущение, что мы проходим. Подходящий flair не найден — поле остаётся пустым и публикация блокируется, случайную метку не отправляем никогда.

## Известные проблемы

- Живой цикл обрывался внутри S5: watchdog писал «cycle has been running for 2700s (state=running); cancelling stale task», а трейсбек всегда показывал `s5_quality/run → gate_post → rewrite → llm/client.py:234 client.post`. Причина не зависший запрос (`llm_timeout_s = 60`), а объём: `_pending_ids` брал до 200 черновиков, у каждого до нескольких перезаписей по 60 с. Закрыто: P22 дала S5 ограниченный по времени кусок, P20 вынес измерение и обучение на часы планировщика. Остаётся запустить это в живом процессе: работающий фарм стартовал в 22:25:59 и не содержит ни одного из сегодняшних коммитов после `1bfe7b1`, поэтому `/api/metrics/formats` в нём 404, а новые задачи планировщика не зарегистрированы. Перезапуск публикующего процесса — действие, которое требует явного согласия оператора (51 publish_unknown и незавершённые циклы в моменте).
- Две линии развития: `github`/`upstream` (Tggruup) = рабочее `main`, `origin` (tgfarm) = `cd21f29` с 16 коммитами, которых нет в `main` (и 27 коммитов `main` нет там; общая предка — чекпоинт P3 `59a5c87`). Слияние «как есть» невозможно: обе линии по-разному переписали `community_policy.py`. Правило переноса: брать намерение, проверять по живым данным. Пример, почему это важно — в ветке фильтр импортированной истории отсекал `Post.angle != "history"`, а `history` в схеме это обычный редакционный угол (992 реальных поста), то есть перенос патча молча выключил бы настоящий кросспостинг. Из ветки ещё не перенесено: финальная перечитка правил непосредственно перед внешним действием (Пикабу `revalidate_pikabu_target`, Reddit — recheck после захвата claim) и отчёт о возможности Reddit в API; `with_fresh_check` в `main` по-прежнему без вызывающего кода. Раньше перенос был отложен намеренно: те же файлы правил агент, и два параллельных редактирования одного контракта — это именно тот неконтролируемый параллелизм, который запрещён. Оба агента вернулись и их работа интегрирована (P23, P24), поэтому владение файлами свободно и это следующий блок.
- CI №830 (run 41599822680) упал на тесте metadata; исправление выполнено и закоммичено в main (локально). Push был заблокирован: GitHub не был подключён в Sharrowkin; 2026-11-04 выполняется отправка накопленных коммитов (445+) в origin/main.
- P3 закрыт 2026-11-04. Принятое решение по контракту: `requirements` = правила назначения (verbatim, инертные) + editorial brief, в таком порядке; `rules_source` никогда не пуст (SELECTOR_RULES_SOURCE); `assess_policy` отдаёт `allow_publish` (гейт не пересчитывает статус).
