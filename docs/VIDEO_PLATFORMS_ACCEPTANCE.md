# YouTube Shorts и TikTok: контролируемая приёмка

Дата: 29.10.2026

Этот runbook закрывает приёмку после объединения PR #49. Зелёный CI подтверждает поведение кода в тестах, но не доказывает, что OAuth-приложение владельца, разрешения и реальные аккаунты настроены корректно.

## Общие правила безопасности

1. Сначала сделай проверенную резервную копию базы: `tgfarm backup`. Продолжай только при `verified: true` и `integrity_check: "ok"`.
2. Выполни `tgfarm doctor` и offline smoke: `tgfarm demo --cycles 1`. Демо может добавить синтетические записи в локальную БД, поэтому для оценки рабочей аналитики используй отдельную копию базы.
3. Оставь платформы выключенными, пока OAuth не завершён и профиль не проверен.
4. Для первого live-теста используй один материал, который допустимо опубликовать и затем удалить. Не запускай массовую очередь.
5. После каждого теста сверяй локальную запись с реальной публикацией на площадке. Сохраняй дату, локальный ID, remote ID/URL, статус до и после перезапуска.
6. Если результат `unknown`, сначала проверь площадку вручную. Не повторяй отправку, пока не установлено, что предыдущая попытка не создала публикацию.
7. Не вставляй access token, refresh token, client secret или OAuth-код в issue, скриншоты, чаты и журналы.

## YouTube Shorts

### Подготовка OAuth

1. Создай/выбери проект в Google Cloud Console и включи YouTube Data API v3.
2. Настрой OAuth consent screen и добавь тестовый аккаунт, если приложение остаётся в режиме Testing.
3. Создай OAuth client подходящего типа для локального приложения и добавь callback URI, который показывает TgFarm в карточке YouTube.
4. В центре площадок открой YouTube, сохрани Client ID и Client Secret, затем запусти подключение через OAuth.
5. На странице согласия проверь запрашиваемые разрешения. Подтверди вход только в собственный тестовый аккаунт.
6. Убедись, что TgFarm показывает ожидаемый канал. Если выбран не тот канал, не включай публикацию.
7. Проверь, что после перезапуска соединение остаётся авторизованным и refresh-token flow работает без вывода токенов в UI или логи.

### Одна тестовая публикация

1. Создай вертикальное видео из существующего поста через штатный video-renderer. Проверь MP4 и текст/метаданные до загрузки.
2. Включи YouTube только для теста и оставь приватность `private`, если UI не предоставляет другого осознанно выбранного режима.
3. Отправь ровно один Short. Не запускай тот же материал повторно, пока не сверишь результат.
4. Открой YouTube Studio и проверь, что видео действительно появилось на нужном канале, открывается и имеет ожидаемые метаданные.
5. Сверь URL/remote ID со статусом TgFarm. Перезапусти приложение и убедись, что материал не отправляется повторно.
6. При неизвестном результате сначала проверь Studio и только затем используй предусмотренное в панели действие сверки.

### Критерии успеха

- OAuth callback не показывает код/токены и не оставляет их в access-логах.
- Проверяется именно выбранный канал.
- Видео загружено как Short и по умолчанию приватное.
- Один локальный материал соответствует одной удалённой загрузке.
- Ошибка/тайм-аут с неизвестным исходом блокирует слепой повтор.

## TikTok Direct Post

### Подготовка OAuth

1. В TikTok for Developers создай приложение и запроси доступ к Content Posting API и необходимые разрешения, включая `user.info.basic` и `video.publish`.
2. Настрой redirect/callback URI в кабинете разработчика точно по значению, которое показывает TgFarm.
3. В центре площадок сохрани параметры приложения и запусти OAuth. Подтверди доступ собственным тестовым аккаунтом.
4. Обнови сведения о creator и проверь доступные варианты приватности/ограничения, которые вернул сам TikTok. Не подставляй варианты вручную, если API их не разрешает.
5. Не включай TikTok в unattended scheduler: текущая интеграция намеренно требует отдельного подтверждения оператора для каждого ролика.

### Одна тестовая отправка

1. Подготовь оригинальный вертикальный MP4 и внимательно просмотри его до отправки.
2. Открой карточку TikTok, проверь аккаунт, описание и параметры приватности.
3. Подтверди только эту конкретную отправку через UI. Не автоматизируй подтверждение и не запускай серию тестов.
4. Проверь состояние публикации в TikTok и сверь его с локальной записью/remote ID.
5. Перезапусти TgFarm и проверь, что тот же материал не отправился повторно.
6. Если статус неизвестен, проверь TikTok вручную. Не повторяй запрос до выяснения результата.

### Критерии успеха

- TikTok остаётся выключенным до явного включения владельцем.
- Каждая отправка требует отдельного подтверждения.
- Используются актуальные ограничения приватности, возвращённые API.
- Неизвестный исход не запускает автоматический повтор.
- Отказ в разрешении или недоступность функции отображается как ошибка/требование настройки, а не как фиктивный успех.
