# T1–T4: сохранённая контрольная точка

Ветка missions/t1-t4-20261106, исходная база 183daa4. Это инкремент реализации, не объявление полной приёмки четырёх миссий.

T1: CLI не выводит произвольный текст исключений и traceback; фиксированная диагностика DemoGateError сохраняет операторский смысл. Начальный вывод токена serve уже был устранён до этой доработки. Исторически раскрытые токены оператору следует ротировать; реальные токены не менялись.

T2: причины horizon_occupied и no_legal_hours сохраняются в payload плана; старые записи сохраняют прежнюю неизвестную причину. API обогащает booking samples через booking_evidence. Передача планировщику фиксирует только реально захваченные UPDATE RETURNING строки и не перезаписывает чужое расписание.

T3: свежая запись с отказным verdict/недоступными правилами не даёт разрешение публикации. Будущая дата проверки не признаётся свежестью. Ошибка хранилища логируется без текста исключения.

T4: ограниченные повторы, Retry-After, circuit breaker, переход к резервному провайдеру без сна из-за первичного, постоянные ошибки без повторов этого провайдера. Отмена нативного редактора восстанавливает payload и закрывает бюджет. Это не доказывает аудит всех потребителей AI budget и всех путей отмены.

Координатор внёс изменения, редактирующие субагенты отсутствуют. Независимое read-only ревью T1–T3 выявило будущую дату и логирование исключения, оба замечания исправлены. Для T4 предыдущие замечания о starvation резервного провайдера воспроизведены тремя падающими тестами и исправлены. Полная независимая приёмка каждого пакета и отдельные исходные worktree не выполнены, WIP был общим при восстановлении.

Последняя адресная проверка: 50 passed (mission regressions, demo gate, ideas); ruff client.py/reliability.py/booking_evidence.py: All checks passed. Compileall прошёл.
