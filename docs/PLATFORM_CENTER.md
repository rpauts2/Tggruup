# Центр площадок TgFarm

Панель «Площадки» — единая точка управления уже подключёнными каналами и будущими интеграциями.

## Что означает переключатель

- **Включена**: новые отправки на эту площадку разрешены, если настроены нужные credentials и сама платформа принимает запросы.
- **Выключена**: новые отправки блокируются; запланированные записи не удаляются и остаются в очереди. После включения они снова смогут отправиться.
- **Нужна настройка**: маршрут поддерживается кодом, но в файле .env отсутствуют обязательные ключи или не найден профиль.
- **В плане интеграций**: приоритет выбран, но рабочего адаптера пока нет. Эта метка не включает публикацию и не создаёт fake-success статусы.

Переключатель не обрывает запрос, который уже передан внешней площадке. Уже начатая отправка может завершиться. Неизвестный результат по-прежнему требует ручной сверки, автоматический дубль не запускается.

## Рабочие интеграции сейчас

| Площадка | Роль | Где задаётся подключение |
|---|---|---|
| Telegram | Основная публикация | TELEGRAM_BOT_TOKEN и целевой канал |
| ВКонтакте | Основные посты и кросспост | VK_ACCESS_TOKEN, VK_GROUP_ID |
| Дзен | Основные статьи через браузерный профиль | Авторизованный профиль браузера Дзена |
| MAX | Кросспост | MAX_ACCESS_TOKEN, MAX_CHANNEL_ID |
| X | Кросспост | X_BEARER_TOKEN, X_USER_ID; права токена нужно проверить отдельно |
| Reddit | Кросспост в один выбранный subreddit | Reddit OAuth client ID/secret, постоянный refresh token, subreddit и User-Agent |

Наличие ключей не считается проверкой авторизации. Используй контролируемый live smoke-test с одной тестовой публикацией на каждой площадке перед ростом объёма.

## Авторизация площадок в панели

В каждой карточке площадки есть отдельная область подключения. Она различает:
- **Доступ подтверждён** — TgFarm выполнил read-only запрос к API либо проверил браузерную сессию, и площадка ответила успешно.
- **Данные сохранены, нужна проверка** — обязательные настройки обнаружены, но их ещё не проверили реальным запросом.
- **Проверка не пройдена** — последние сохранённые учётные данные отклонены или сессия не авторизована.
- **Интеграция пока не подключена** — кнопка открывает сайт для ручного входа/настройки аккаунта, но публикация в TgFarm не реализована.

Кнопки не запрашивают пароль пользователя от соцсети в TgFarm и не обещают OAuth там, где он ещё не написан. Для встроенных адаптеров токены можно записать из панели: вводимые значения сохраняются в локальный `.env`, секреты никогда не отправляются обратно на клиент и не включаются в журнал. Пустое поле означает «не изменять сохранённое значение». Замена ключа сбрасывает старый подтверждённый статус до повторной проверки. Файл обновляется атомарно; права ограничиваются до `0600` там, где ОС поддерживает chmod. Храни `.env` вне Git и резервных копий, которые кому-то доступны.

Для Telegram проверка подтверждает token через `getMe`, но не проверяет право бота публиковать в конкретный канал. Для VK, MAX и X проверяется доступ к данным профиля/сообщества, а не write-доступ. Для Reddit проверяется OAuth и чтение выбранного subreddit; scope `submit` и первая публикация проверяются отдельно. Только контролируемый smoke-test может подтвердить фактическую публикацию.

Для Дзена кнопка открывает рабочее headed-окно входа в Яндекс и сохраняет сессию в выделенный профиль браузера. Для социальных сетей без адаптера кнопка лишь открывает сайт и сообщает об ограничении. Когда API-адаптер появится, его проверка должна быть реализована отдельно.

## Reddit: первый рабочий адаптер

- Публикует нативный текстовый пост по умолчанию; для контролируемого workflow возможен link-пост.
- Целевое сообщество берётся из `REDDIT_SUBREDDIT`. Можно передать `meta.subreddit` в payload, если конкретный workflow уже определил community.
- Идентификатор, URL и состояние отправки сохраняются в общем журнале кросспостинга. Неопределённый результат не запускает автоматический повтор, чтобы не создавать дубль.
- Адаптер требует `REDDIT_CLIENT_ID`, `REDDIT_CLIENT_SECRET`, `REDDIT_REFRESH_TOKEN`, `REDDIT_SUBREDDIT` и уникальный `REDDIT_USER_AGENT`. Используй OAuth с разрешением `submit` и permanent refresh token; пароль аккаунта не хранится.
- Глобальный переключатель по умолчанию выключен. Сначала проверь, что Reddit разрешил твоему приложению API-доступ, и выполни одну тестовую публикацию в сообщество, где правила действительно допускают такой контент.
- Внизу панели есть Scout: поиск до восьми сообществ, оценка совпадения, чтение доступных правил/технических ограничений и отдельный редакторский черновик на базе опубликованного поста.
- Перед отправкой сервер повторно сверяет машинно-читаемые ограничения; если обязателен flair, который UI ещё не умеет выбирать, публикация блокируется.
- Адаптер не публикует комментарии, не ставит голоса, не отправляет личные сообщения и не рассылает один пост массово по разным subreddit. Следуй правилам конкретных сообществ и ограничениям Reddit API.

Официальная документация: [Reddit API](https://www.reddit.com/dev/api/) и [правила Data API](https://support.reddithelp.com/hc/en-us/articles/16160319875092-Reddit-Data-API-Wiki). Пошаговая настройка: [REDDIT_SETUP.md](REDDIT_SETUP.md).

## Метрики и обучение Reddit Scout

В секции Scout появилась кнопка обновления статистики и карточки результатов по сообществам. Для подтверждённых Reddit-постов собираются только доступные через стандартный Data API поля: score, число комментариев и upvote ratio. Срезы сохраняются во временной ряд; повторное нажатие в пределах 15 минут обновляет последний срез, а не создаёт новый. Обход ограничен 100 публикациями за запрос, кнопка собирает до 50.

Scout использует историю TgFarm как небольшой ограниченный бонус к тематическому совпадению. Размер выборки показан отдельно; малое число постов не трактуется как достоверный сигнал. Если данных нет, рейтинг продолжает работать на описаниях/активности сообществ. Просмотры и показы из этого API-запроса не предполагаются и не подставляются синтетически. Метрики никогда не меняют статус публикации и не запускают повторный пост.

## Каталог следующих интеграций

### Следующая очередь: P1

1. **YouTube**. Загрузка видео и Shorts, название, описание, теги и обложка. Нужен отдельный видео-конвейер и OAuth.
2. **TikTok**. Короткие вертикальные видео; потребуются субтитры, адаптация ролика, OAuth и допуск к Content Posting API.
3. **Instagram**. Reels, изображения и карусели. API-публикация зависит от типа аккаунта, прав Meta и доступов приложения.
4. **Одноклассники**. Отдельная версия контента для российской аудитории, после проверки доступного официального API.
5. **RUTUBE**. Видео и клипы, после подтверждения актуального официального способа загрузки.

### Вторая очередь: P2

- **Threads**: короткие сообщения, визуальные заметки.
- **Facebook Pages**: публикации на страницах; это не универсальный постинг в личный профиль.
- **LinkedIn**: экспертные материалы, B2B и публикации организации. Права API и версия endpoint требуют проверки при реализации.
- **Pinterest**: вертикальные карточки/пины, ведущие на первоисточник или статью.
- **Bluesky**: короткие посты и карточки ссылок через AT Protocol.
- **Discord**: анонсы в принадлежащие владельцу серверы через бота или webhook.
- **vc.ru**, **Хабр**: отдельные статьи, а не простое копирование поста.
- **TenChat**: деловые публикации с отдельной редактурой.

### Третья очередь: P3

- **Mastodon**: федеративные сети, настройки серверов отличаются.
- **WhatsApp Channels**: проверять отдельно. WhatsApp Business Messaging API не следует путать с API управления Channels.
- **Medium**: статьи; прежде реализации необходимо подтвердить доступный API создания публикаций.
- **Пикабу**, **Tumblr**: нишевые посты и визуальные сообщества.
- **Twitch**: анонсы трансляций и клипы.
- **Snapchat**: вертикальные видео при наличии доступа к нужному продукту публикации.
- **WeChat/Weixin**, **Douyin**, **RedNote/Xiaohongshu**: региональные интеграции; потребуют отдельной стратегии, локализации и проверки доступов.

## Почему приоритет такой

Для русскоязычной аудитории разумно сначала довести VK, Telegram, MAX, Дзен и видео-маршруты YouTube/TikTok/RUTUBE. Для международного охвата уместны Reddit, YouTube, TikTok, Instagram, Threads, Facebook Pages, LinkedIn, Pinterest и Bluesky. Reddit уже подключён как кросспост-адаптер, но включать его следует только после проверки OAuth и правил выбранного subreddit.

Это стартовый приоритет, а не универсальный рейтинг популярности. Приоритет стоит менять под географию, тематику, аудиторию и фактические результаты конкретных каналов.

## Как добавить новый адаптер правильно

1. Проверить актуальную официальную документацию, разрешения приложения и правила публикации.
2. Реализовать самостоятельный адаптер с форматированием, медиа, ограничениями, rate-limit и классификацией ошибок.
3. Сохранить remote ID/URL и идемпотентность. После timeout нельзя повторять отправку вслепую.
4. Добавить offline-тесты и тесты ошибок; новая площадка остаётся в режиме «план» до завершения проверки.
5. Выполнить одну контролируемую live-публикацию, сверить её вручную, затем постепенно наращивать объём.

Состояние каталога хранится в config/platforms.yaml. Секреты и токены в этот файл не записываются: держи их в .env или секрет-хранилище.
