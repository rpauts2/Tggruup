# Центр площадок TgFarm

Панель «Площадки» — единая точка управления уже подключёнными каналами и будущими интеграциями.

## Что означает переключатель

- **Включена**: новые отправки на эту площадку разрешены, если настроены нужные credentials и сама платформа принимает запросы.
- **Выключена**: новые отправки блокируются; запланированные записи не удаляются и остаются в очереди. После включения они снова смогут отправиться.
- **Нужна настройка**: маршрут поддерживается кодом, но в файле .env отсутствуют обязательные ключи или не найден профиль.
- **В плане интеграций**: приоритет выбран, но рабочего адаптера пока нет. Эта метка не включает публикацию и не создаёт fake-success статусы.

Переключатель не обрывает запрос, который уже передан внешней площадке. Уже начатая отправка может завершиться. Неизвестный результат по-прежнему требует ручной сверки, автоматический дубль не запускается.

## LinkedIn: OAuth и нативная публикация

Для подключения создай приложение в [LinkedIn Developer Portal](https://www.linkedin.com/developers/) и добавь продукты **Sign In with LinkedIn using OpenID Connect** и **Share on LinkedIn**. В карточке площадки нажми «Настроить приложение» и сохрани Client ID/Client Secret. Затем нажми «Подключить через OAuth», скопируй callback URI из окна подтверждения и добавь его в Authorized redirect URLs в кабинете LinkedIn. Запрашиваются только `openid`, `profile` и `w_member_social`; разрешение публикации доступно лишь когда его выдал LinkedIn для приложения.

TgFarm использует authorization-code flow с одноразовым случайным `state`, обменивает код на пользовательский access token и проверяет профиль через OpenID Connect `userinfo`. Коды и токены не возвращаются в браузер и удаляются из callback query string до access-логирования. Учётные данные хранятся в локальном `.env`. Если LinkedIn выдал refresh token, TgFarm пытается обновить истекающий access token и сохраняет ротированные значения; если refresh token не выдан, после истечения срока потребуется повторно подключить аккаунт.

Для публикации используется `POST https://api.linkedin.com/rest/posts` с заголовками `LinkedIn-Version: 202610` и `X-Restli-Protocol-Version: 2.0.0`. Текущая реализация публикует только текст от имени подключённого участника, без изображений, видео и публикаций от имени организации. После принятия публикации сохраняется `x-restli-id`; если LinkedIn не вернул ID, результат остаётся неопределённым, чтобы ферма не создала возможный дубль автоматически.

LinkedIn выключен по умолчанию. После успешного OAuth включи площадку вручную и сначала сделай один тестовый пост, который можно удалить. Реальная возможность публикации зависит от доступа приложения к продукту и разрешению `w_member_social`, а также актуальных правил, версий и лимитов LinkedIn API.

## Threads: OAuth и публикация текстовых постов

Для подключения нужен Meta Developer App с добавленным продуктом Threads API. В карточке Threads нажми «Настроить приложение», сохрани **Threads App ID** и **Threads App Secret**, затем нажми «Подключить через OAuth». Перед подтверждением добавь показанный callback URL в Threads API → OAuth Redirect URIs и разреши `threads_basic` и `threads_content_publish`. В режиме разработки подключаемый аккаунт должен быть добавлен к ролям/тестерам приложения; доступ к API зависит от состояния и проверки самого Meta App.

TgFarm обменивает одноразовый OAuth-код на краткоживущий токен, затем запрашивает долгоживущий пользовательский токен и проверяет профиль через `GET /v1.0/me`. Код, state и токены не возвращаются в браузер и очищаются из query string до access-логирования. Токен сохраняется в локальном `.env`; при приближении срока окончания он обновляется через Threads API. Публикация использует двухшаговый процесс: создать текстовый контейнер `/threads`, затем отправить его через `/threads_publish`. После успешной отправки TgFarm старается получить permalink.

Поддерживается текстовая публикация; фото, видео и карусели здесь пока не реализованы. Threads выключен по умолчанию, поэтому после успешного OAuth сначала включи площадку и протестируй одну публикацию на собственном аккаунте. Внешний Meta App, его redirect URI, разрешения и режим доступа должны быть настроены на стороне владельца приложения.

## Bluesky: подключение и публикация

Bluesky добавлен как рабочий адаптер AT Protocol для коротких текстовых постов. В карточке сети введи handle (например, `name.bsky.social`) и **app password**, созданный в Settings → Privacy and Security → App passwords. Не используй основной пароль аккаунта. TgFarm получает краткоживущую сессию через `com.atproto.server.createSession` и создаёт запись через `com.atproto.repo.createRecord`; пароль не возвращается в UI и не попадает в логи. Поддерживается текст, не видео/карусели; длина текста ограничивается безопасным базовым пределом. Bluesky выключен по умолчанию: после проверки авторизации включи его в каталоге и сначала проверь публикацию на собственном аккаунте в режиме `live`.

## Mastodon: вход через OAuth 2.0 + PKCE

В карточке Mastodon нажми «Подключить через OAuth» и укажи адрес своего сервера, например \`https://mastodon.social\`. TgFarm зарегистрирует OAuth-приложение на выбранном инстансе, откроет страницу согласия и запросит только \`read\` и \`write:statuses\`. Пароль Mastodon не вводится и не сохраняется: после согласия приложение получает пользовательский токен и проверяет профиль через \`accounts/verify_credentials\`. Код возврата и OAuth state не попадают в сообщения журнала; callback захватывает только необходимые параметры и очищает query string до вызова обработчиков. Токен и client secret сохраняются локально в \`.env\`. Mastodon выключен по умолчанию.

Адаптер публикует текстовые статусы, ограничивает тело 500 символами как безопасным базовым лимитом и передаёт \`Idempotency-Key\`, поддерживаемый Mastodon для защиты от дублирующих запросов. Сначала включи площадку и проверь одну тестовую публикацию на собственном аккаунте. На старых инстансах PKCE может быть недоступен, поэтому подключение требует современный Mastodon с поддержкой PKCE.

## X: OAuth 2.0 для пользовательской публикации

Старый app-only Bearer token подходит для части read-запросов, но сам по себе не является пользовательским разрешением на создание постов. Поэтому публикация X переведена на OAuth 2.0 Authorization Code + PKCE: TgFarm запрашивает только \`tweet.read\`, \`users.read\`, \`tweet.write\` и \`offline.access\`, получает профиль через \`/2/users/me\` и сохраняет access/refresh-токены в локальный \`.env\`. Пароль X не запрашивается. Access token обновляется по refresh token, включая сохранение нового refresh token, когда X его ротирует.

Перед подключением создай приложение в [X Developer Portal](https://developer.x.com/), включи OAuth 2.0, выбери confidential/Web App тип клиента и скопируй Client ID и Client Secret в «Настроить приложение» в TgFarm. При нажатии «Подключить через OAuth» панель покажет точный Callback URI: добавь его в настройки X до продолжения. Callback обрабатывает одноразовый state, использует PKCE и очищает query string до access-логирования, так как X рекомендует не журналировать authorization code. Публикация остаётся отключённой в настройках до ручного включения и проверочной публикации.

Текущая X API доступность и цена зависят от проекта и лимитов на стороне X. TgFarm не обходит эти ограничения; при ошибке публикации проверь доступ к endpoint создания поста и разрешение \`tweet.write\`.

## Авторизация площадок в панели

В каждой карточке площадки есть отдельная область подключения. Она различает:
- **Доступ подтверждён** — TgFarm выполнил read-only запрос к API либо проверил браузерную сессию, и площадка ответила успешно.
- **Данные сохранены, нужна проверка** — обязательные настройки обнаружены, но их ещё не проверили реальным запросом.
- **Проверка не пройдена** — последние сохранённые учётные данные отклонены или сессия не авторизована.
- **Интеграция пока не подключена** — кнопка открывает сайт для ручного входа/настройки аккаунта, но публикация в TgFarm не реализована.

Кнопки не запрашивают пароль пользователя от соцсети в TgFarm и не обещают OAuth там, где он ещё не написан. Для встроенных адаптеров токены можно записать из панели: вводимые значения сохраняются в локальный `.env`, секреты никогда не отправляются обратно на клиент и не включаются в журнал. Пустое поле означает «не изменять сохранённое значение». Замена ключа сбрасывает старый подтверждённый статус до повторной проверки. Файл обновляется атомарно; права ограничиваются до `0600` там, где ОС поддерживает chmod. Храни `.env` вне Git и резервных копий, которые кому-то доступны.

Для Telegram проверка подтверждает token через `getMe`, но не проверяет право бота публиковать в конкретный канал. Для VK, MAX и X проверяется доступ к данным профиля/сообщества, а не write-доступ. Для Reddit проверяется OAuth и чтение выбранного subreddit; scope `submit` и первая публикация проверяются отдельно. Только контролируемый smoke-test может подтвердить фактическую публикацию.

Для Дзена кнопка открывает рабочее headed-окно входа в Яндекс и сохраняет сессию в выделенный профиль браузера. Для социальных сетей без адаптера кнопка лишь открывает сайт и сообщает об ограничении. Когда API-адаптер появится, его проверка должна быть реализована отдельно.

## Reddit: первый рабочий адаптер

- Публикует нативный текстовый пост по умолчанию; для контролируемого workflow возможен link-пост.
- Целевое сообщество берётся из `REDDIT_SUBREDDIT`. Можно передать `meta.subreddit` в payload, если конкретный workflow уже определил community.
- Идентификатор, URL и состояние отправки сохраняются в общем журнале кросспостинга. Неопределённый результат не запускает автоматический повтор, чтобы не создавать дубль.
- Адаптер требует `REDDIT_CLIENT_ID`, `REDDIT_CLIENT_SECRET`, `REDDIT_REFRESH_TOKEN`, `REDDIT_SUBREDDIT` и уникальный `REDDIT_USER_AGENT`. Используй OAuth с разрешением `submit` и permanent refresh token; пароль аккаунта не хранится.
- Глобальный переключатель по умолчанию выключен. Сначала проверь, что Reddit разрешил твоему приложению API-доступ, и выполни одну тестовую публикацию в сообщество, где правила действительно допускают такой контент.
- Внизу панели есть Scout: поиск до восьми сообществ, оценка совпадения, чтение доступных правил/технических ограничений и отдельный редакторский черновик на базе опубликованного поста.
- Перед отправкой сервер повторно сверяет машинно-читаемые ограничения; если обязателен flair, который UI ещё не умеет выбирать, публикация блокируется.
- Адаптер не публикует комментарии, не ставит голоса, не отправляет личные сообщения и не рассылает один пост массово по разным subreddit. Следуй правилам конкретных сообществ и ограничениям Reddit API.

Официальная документация: [Reddit API](https://www.reddit.com/dev/api/) и [правила Data API](https://support.reddithelp.com/hc/en-us/articles/16160319875092-Reddit-Data-API-Wiki). Пошаговая настройка: [REDDIT_SETUP.md](REDDIT_SETUP.md).

## Метрики и обучение Reddit Scout

В секции Scout появилась кнопка обновления статистики и карточки результатов по сообществам. Для подтверждённых Reddit-постов собираются только доступные через стандартный Data API поля: score, число комментариев и upvote ratio. Срезы сохраняются во временной ряд; повторное нажатие в пределах 15 минут обновляет последний срез, а не создаёт новый. Обход ограничен 100 публикациями за запрос, кнопка собирает до 50.

Scout использует историю TgFarm как небольшой ограниченный бонус к тематическому совпадению. Размер выборки показан отдельно; малое число постов не трактуется как достоверный сигнал. Если данных нет, рейтинг продолжает работать на описаниях/активности сообществ. Просмотры и показы из этого API-запроса не предполагаются и не подставляются синтетически. Метрики никогда не меняют статус публикации и не запускают повторный пост.

## Discord: webhook публикация

Discord включён как рабочая цель S9 для принадлежащих владельцу серверов и каналов. Вставь `DISCORD_WEBHOOK_URL` из настроек канала. TgFarm проверяет webhook read-only запросом `GET` и не посылает тестовых сообщений при проверке. Публикация использует `wait=true`, чтобы получить подтверждённый message ID; `allowed_mentions.parse` пуст, поэтому сообщения фермы не вызывают `@everyone` и массовые mentions. Для форумных каналов требуется конкретный `thread_id` в метаданных назначения; автоматический выбор ветки пока не включён.

Webhook URL фактически является секретом доступа к каналу: храни его только в локальном `.env`, не вставляй в скриншоты и при утечке сразу перевыпусти webhook в Discord.

## Instagram: OAuth, фото и Reels

Instagram теперь является рабочей целью S9 для одиночных JPEG-фото и Reels. Адаптер использует Instagram Login scopes `instagram_business_basic` и `instagram_business_content_publish`, создаёт media container, ждёт окончания обработки Reels, публикует контейнер и сохраняет возвращённый media ID/permalink.

Для передачи медиа Meta скачивает файл по публичному HTTPS URL. Укажи внешний origin в `TGFARM_PUBLIC_BASE_URL`; endpoint `/public/instagram-media/{id}` отдаёт только активы опубликованных постов по короткоживущей HMAC-подписи. Переключатель выключен по умолчанию. Начни с одной контролируемой публикации и проверь результат в самом Instagram.

LinkedIn member posts используют официальный Posts API и `w_member_social`; публикации от имени организации текущий адаптер не выполняет. TikTok остаётся ручной целью на каждое видео: перед Direct Post ферма обязана получить свежие настройки автора и явное согласие владельца.

## Pinterest: OAuth и image Pins

Pinterest включён как рабочая цель S9 для image Pins. Подключи приложение через Pinterest OAuth с разрешениями `boards:read`, `pins:read`, `pins:write`, заранее укажи ID доски и заверши авторизацию. Callback проверяет, что подключённый пользователь действительно имеет доступ к выбранной доске. Access и rotating refresh token хранятся в локальном `.env`; access token обновляется автоматически до истечения.

Для image Pin ферма использует собственную обложку поста и `POST /v5/pins` с `media_source.source_type=image_url`. Pinterest скачивает файл по короткоживущей HMAC-ссылке `/public/instagram-media/{id}` на публичном HTTPS-домене `TGFARM_PUBLIC_BASE_URL`. Переключатель выключен по умолчанию. Сейчас поддерживается формат image Pin; видео требует отдельной последовательности `POST /v5/media`, загрузки multipart на выданный URL, проверки статуса и создания Pin с `video_id`, поэтому видео не будет ошибочно отправлено как фотография.

## Каталог следующих интеграций

### Следующая очередь: P1

1. **YouTube / Shorts**. Интеграционный слой уже реализован: Google OAuth, refresh token, проверка связанного канала и resumable upload через [YouTube Data API](https://developers.google.com/youtube/v3/docs/videos/insert). Видео загружается с приватностью `private` по умолчанию; настройка аудитории не должна автоматически повышаться до публичной. Адаптер включён как доступная интеграция, но выключен в конфигурации по умолчанию. Перед эксплуатацией нужны действительные Google credentials, доступ к YouTube Data API и контролируемая тестовая загрузка.
2. **TikTok**. Видеорендерер готовит вертикальный MP4; publisher ещё не реализован. Нужен [Content Posting API](https://developers.tiktok.com/products/content-posting-api/), разрешённый scope `video.publish`, чтение настроек создателя, явное подтверждение владельца и выбранной приватности для каждого ролика, а затем статусная сверка. До аудита приложения публикации могут быть ограничены приватным просмотром.
3. **VK Клипы**. Отдельная интеграция, не синоним обычной записи в стену и не гарантированный побочный эффект `video.save`. Нужно подтвердить официально поддерживаемый clip-specific сценарий загрузки/публикации, права сообщества и обработку результата, прежде чем включать live-режим.
4. **Instagram**. Reels, изображения и карусели. API-публикация зависит от типа аккаунта, прав Meta и доступов приложения.
5. **Одноклассники**. Отдельная версия контента для российской аудитории, после проверки доступного официального API.
6. **RUTUBE**. Видео и клипы, после подтверждения актуального официального способа загрузки.

### Вторая очередь: P2

- **Threads**: короткие сообщения, визуальные заметки.
- **Facebook Pages**: публикации на страницах; это не универсальный постинг в личный профиль.
- **LinkedIn**: публикация от имени личного профиля уже подключена; отдельная интеграция для организаций потребует organization scopes и ролей.
- **Bluesky**: короткие посты и карточки ссылок через AT Protocol.
- **Discord**: анонсы в принадлежащие владельцу серверы через бота или webhook.
- **vc.ru**, **Хабр**: отдельные статьи, а не простое копирование поста.
- **TenChat**: деловые публикации с отдельной редактурой.

### Третья очередь: P3

- **Mastodon**: федеративные сети, настройки серверов отличаются.
- **WhatsApp Channels**: проверять отдельно. WhatsApp Business Messaging API не следует путать с API управления Channels.
- **Medium**: статьи; прежде реализации необходимо подтвердить доступный API создания публикаций.
- **Пикабу**, **Tumblr**: нишевые посты и визуальные сообщества.
- **Twitch**: анонсы трансляций и клипы.
- **Snapchat**: вертикальные видео при наличии доступа к нужному продукту публикации.
- **WeChat/Weixin**, **Douyin**, **RedNote/Xiaohongshu**: региональные интеграции; потребуют отдельной стратегии, локализации и проверки доступов.

## Почему приоритет такой

Для русскоязычной аудитории разумно сначала довести VK, Telegram, MAX, Дзен и видео-маршруты YouTube/TikTok/VK Клипов/RUTUBE. Для международного охвата уместны Reddit, YouTube, TikTok, Instagram, Threads, Facebook Pages, LinkedIn, Pinterest и Bluesky. Reddit уже подключён как кросспост-адаптер, но включать его следует только после проверки OAuth и правил выбранного subreddit.

Это стартовый приоритет, а не универсальный рейтинг популярности. Приоритет стоит менять под географию, тематику, аудиторию и фактические результаты конкретных каналов.

## Как добавить новый адаптер правильно

1. Проверить актуальную официальную документацию, разрешения приложения и правила публикации.
2. Реализовать самостоятельный адаптер с форматированием, медиа, ограничениями, rate-limit и классификацией ошибок.
3. Сохранить remote ID/URL и идемпотентность. После timeout нельзя повторять отправку вслепую.
4. Добавить offline-тесты и тесты ошибок; новая площадка остаётся в режиме «план» до завершения проверки.
5. Выполнить одну контролируемую live-публикацию, сверить её вручную, затем постепенно наращивать объём.

Состояние каталога хранится в config/platforms.yaml. Секреты и токены в этот файл не записываются: держи их в .env или секрет-хранилище.
