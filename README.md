# tgfarm — автономная ферма каналов

**Центр площадок:** открой вкладку «Площадки», чтобы управлять каналами и интеграциями. [Каталог](docs/PLATFORM_CENTER.md). Рабочие адаптеры доступны для Telegram, VK, Дзена, MAX, X, Reddit, Bluesky, Mastodon, Threads, LinkedIn, YouTube, TikTok (каждый ролик требует отдельного подтверждения), Douyin (отдельное подтверждение каждого видео), Instagram, Facebook Pages, Pinterest, Одноклассников, Discord и Tumblr. Новые интеграции выключены по умолчанию; для каждой сначала проверь OAuth/API-доступ и выполни контролируемую тестовую публикацию.

Открой карточку поста и блок «Ручная подготовка для остальных площадок»: он выдаёт платформенный текстовый пакет и ссылки на доступное медиа для ручной отправки через официальный редактор.

Проверка авторизации настроенных и включённых площадок выполняется при запуске и далее каждые 6 часов. Watchdog отдельно показывает отказ доступа (`platform_auth_failed`) и остановку самого мониторинга (`platform_auth_monitor_missing` / `platform_auth_monitor_stale`). Порог свежести настраивается через `PLATFORM_AUTH_MAX_AGE_HOURS` (по умолчанию 12 часов). Проверка read-only и не публикует тестовые посты.


**Перед live-запуском:** следуй [контролируемому smoke-test VK/Дзена](docs/SMOKE_TEST_VK_DZEN.md). Для проверенной копии SQLite используй `tgfarm backup`; импорт истории в режиме `--apply` автоматически требует успешную резервную копию.
Офлайн-команда `tgfarm demo --cycles 1` принудительно использует режим `off`, чтобы синтетические посты не ушли на площадки даже при `TGFARM_MODE=live`; при этом демо добавляет синтетические данные в локальную БД.

Конвейер, который сам ищет тренды, пишет посты, рисует обложки, проходит
собственные проверки качества, планирует публикации по реальным часам пика,
публикует в Telegram и Дзен и кросспостит во внешние платформы. Запускается
одной командой.

```
S1 сбор → S2 тренды → S4 генерация → S5 качество → S6 визуал
      → S7 планирование и публикация → S9 кросспост → S8 аналитика
```

Работает **без единого API-ключа**: LLM и векторизация деградируют до
детерминированных офлайн-реализаций, публикация — в dry-run. Ключи подключаются
по одной, ничего не ломая.

## Быстрый старт

### Готовый `.exe`

```powershell
dist\TgFarm\TgFarm.exe
```

Распакованная сборка со всем рантаймом внутри: Python и зависимости уже там,
интерпретатор не нужен. При первом запуске рядом с `.exe` появляются `config/`
(копия настроек, которую можно править), `data/` (база, медиа, журналы) и
`.env.example`. Закрытие окна сворачивает приложение в трей — публикация идёт
дальше.

### Из исходников

```bash
python -m venv .venv
.\.venv\Scripts\pip install -e ".[dev,dzen]"     # Windows
# python3 -m venv .venv && pip install -e ".[dev]"   # Linux/macOS

copy .env.example .env                           # cp на Linux/macOS

python -m tgfarm.cli doctor                      # проверить окружение
python -m tgfarm.cli demo                        # полный прогон на синтетике
python -m tgfarm.cli desktop                     # desktop-окно + планировщик
python -m tgfarm.cli serve                       # то же самое в браузере
```

`doctor` проверяет конфигурацию, провайдеры, каналы и теперь также общий operational-watchdog: свежесть источников и backup, очередь публикаций, авторизацию и доставку алертов. Он использует те же коды проблем, что API и панель, без вывода секретов.

Для черновиков с углом `news` quality gate проверяет даты первоисточников в архиве. Если все прикреплённые источники имеют известную дату публикации и каждый старше `SOURCE_MAX_AGE_HOURS` (72 часа по умолчанию), черновик отклоняется до повторной генерации: переписывание не делает факты свежее. Неизвестная дата не считается доказательством устаревания, а форматы `analysis` и другие не-news углы могут использовать старые источники.

S4 дополнительно проводит независимый аудит явных календарных дат в тексте: форматы `YYYY-MM-DD`, `DD.MM.YYYY`, русские и английские даты словами нормализуются к одной календарной дате. Если предложение содержит полную дату, которой нет целиком хотя бы в одном из прикреплённых источников, факт-гейт отклоняет черновик. Отдельный год без дня и месяца остаётся под существующим числовым аудитом.

Публикация обновляет `publish_heartbeat_at` каждые 30 секунд, пока задача остаётся активной. Watchdog определяет зависание по последнему heartbeat, а для старых записей без него использует время начала попытки. После подтверждённого успеха или ошибки heartbeat очищается. Если задача отменена при остановке или восстановлении, heartbeat останавливается, а пост переходит в `publish_unknown`. Любой неизвестный результат требует ручной сверки перед повтором, чтобы не создавать дубли.

Повторные ошибки основной публикации ограничены `PRIMARY_PUBLISH_MAX_ATTEMPTS` (5 по умолчанию). Явные HTTP 4xx-отказы, кроме временных 408/425/429, становятся терминальным статусом `failed`; неизвестный исход по-прежнему переходит в `publish_unknown`, а не в повтор. После исправления причины оператор может нажать «Повторить после исправления»: это действие доступно только для определённого отказа и сбрасывает лимит попыток. Watchdog поднимает `publish_terminal_failure`, пока такие посты ждут решения.

Для HTTP 429 первичная публикация уважает `Retry-After` в секундах или HTTP-date; для Telegram-подобных исключений читается и поле `retry_after`. Задержка ограничена 24 часами. Ответы 5xx/тайм-ауты, которые могли произойти после принятия поста, не превращаются в слепой повтор: они остаются `publish_unknown` до ручной сверки.
 
`demo` прогоняет весь конвейер на шести синтетических сюжетах, размазанных по
нескольким изданиям, и печатает отчёт по каждому этапу. Это и есть проверка
работоспособности: она не требует ни сети, ни ключей.

### Создание вертикального видео

У уже сохранённого поста можно создать оригинальный короткий ролик из титров и текста:

```bash
python -m tgfarm.cli posts --limit 10
python -m tgfarm.cli video-render POST_PUBLIC_ID
```

Рендерер делает MP4 в формате 1080×1920, добавляет короткие сцены с движением кадра и сохраняет JSON-манифест рядом с файлом. Видео прикрепляется к посту как дополнительный медиа-ассет, не заменяя обложку. Рендерер не скачивает чужие ролики и не генерирует факты, отсутствующие в тексте исходного поста. Для сборки нужен установленный FFmpeg в PATH.

**YouTube / Shorts:** в панели площадок есть OAuth-подключение Google, проверка канала и загрузчик YouTube Data API v3 с resumable upload. Для настройки создай OAuth Client типа Web application в Google Cloud Console, включи YouTube Data API v3 и добавь callback URI панели `/api/platforms/youtube/auth/callback`. Потребуются scopes `youtube.upload` и `youtube.readonly`. Новые загрузки по умолчанию получают приватность `private`; YouTube надо включить отдельно после подключения канала и контролируемого теста. Если в публикации нет готового видео, live-конвейер попробует создать Short из текста поста. Для реального доступа нужны действительные ключи Google, разрешённый OAuth grant и квота API.

**LinkedIn:** подключённые личные профили могут автоматически публиковать текст через Posts API и разрешение `w_member_social`. Для организаций потребуются отдельные organization scopes и роль администратора, это не включено в текущий адаптер.

**Pinterest:** подключается через Pinterest OAuth. Укажи App ID/Secret и ID существующей доски, затем подтверди разрешения `boards:read`, `pins:read`, `pins:write`. TgFarm проверяет доступ к выбранной доске и публикует image и video Pins с ссылкой на первоисточник. Для фото и обложек видео нужен настроенный `TGFARM_PUBLIC_BASE_URL`, чтобы Pinterest мог скачать файл по краткоживущей подписанной ссылке. Видео проходит отдельную регистрацию в Media API, загрузку на выданный URL и проверку статуса до создания Pin.

**Одноклассники:** подключаются через официальный REST API группы. Введи `OK_APPLICATION_KEY`, `OK_APPLICATION_SECRET`, `OK_ACCESS_TOKEN` и `OK_GROUP_ID`. Для публикации от имени группы приложению нужны `GROUP_CONTENT`, для фото дополнительно `PHOTO_CONTENT`, для видео `VIDEO_CONTENT`. Запроси у `api-support@ok.ru` разрешения `VALUABLE_ACCESS`, `LONG_ACCESS_TOKEN`, `GROUP_CONTENT`, `PHOTO_CONTENT` и `VIDEO_CONTENT`; долгоживущий токен продлевается при регулярных API-вызовах. Если из кабинета выдан отдельный `session_secret_key`, сохрани его; иначе TgFarm рассчитывает подпись официальным способом.

**Discord:** подключается через webhook в собственном сервере/канале. TgFarm проверяет webhook read-only запросом и публикует сообщения с подтверждением Discord; `@everyone` и массовые mentions запрещены. Webhook URL хранится только в локальном `.env`, поэтому не отправляй его в чаты и не добавляй в скриншоты.

**Instagram:** доступны Instagram Login OAuth и нативная публикация JPEG-фото/Reels через Content Publishing API. Для передачи медиа Meta забирает файл с публичного HTTPS-адреса: укажи внешний origin в `TGFARM_PUBLIC_BASE_URL` (без завершающего `/`) и пробрось путь `/public/instagram-media/` на TgFarm. Временные ссылки подписываются HMAC и отдают только медиа уже опубликованных постов. Переключатель Instagram по умолчанию выключен: сначала проверь OAuth и выполни один контролируемый пост.

**Douyin:** использует отдельный от TikTok Open Platform API. Создай Web App в Douyin Open Platform и запроси scopes user_info и video.create. Callback URL из панели должен быть разрешён в настройках приложения. TgFarm показывает оригинальный MP4 и подпись до 1000 символов и требует отдельное подтверждение перед каждым созданием видео. Официальный API сначала загружает файл, затем создаёт видео; после создания ролик проходит модерацию и временно может быть виден только автору.

**TikTok:** в разделе «Площадки» доступны OAuth и проверка аккаунта через Content Posting API. В карточке опубликованного поста кнопка «Подготовить TikTok» создаёт/находит MP4, показывает превью и получает актуальные privacy options автора. Direct Post запускается только после отдельной отметки согласия на конкретное видео; при неизвестном результате повтор блокируется до ручной сверки. Настрой TikTok Developer App, callback URI `/api/platforms/tiktok/auth/callback`, разрешения `user.info.basic` и `video.publish`. До аудита приложения TikTok может ограничивать видимость API-публикаций приватным режимом.

**VK Клипы:** готовый вертикальный MP4 можно скачать прямо из карточки поста и загрузить через [официальный раздел Клипов VK](https://vk.com/clips). TgFarm не отображает фальшивый статус «опубликовано»: прямую загрузку именно в ленту Клипов не считаем API-интеграцией, пока не подтверждён подходящий официальный endpoint.

## Desktop-приложение

Так устроены Discord, Slack, VS Code и Notion: нативное окно с меню поверх
веб-технологий. Это не компромисс, а рабочая схема — она даёт свой визуальный
слой без затрат на собственный рендерер.

| Возможность | Зачем |
|---|---|
| Нативное окно 1440×900, своя иконка | Приложение, а не вкладка браузера |
| Меню **Файл / Ферма / Вид / Справка** | Папка данных, запуск цикла, переходы, `doctor` — в одном месте |
| Трей, закрытие сворачивает окно | Уборка панели задач не должна останавливать публикацию |
| Планировщик внутри процесса | Окно закрыто — конвейер работает |
| Случайный порт на `127.0.0.1` | Две копии не столкнутся, наружу ничего не выставлено |
| `data/desktop.lock` с pid | Второй экземпляр не запустится; после краша — подхватит |
| Мост `window.pywebview.api` | Нативные действия из страницы: папка, уведомление, цикл |

От `tgfarm serve` отличается только оболочка: тот же API, та же панель, тот же
планировщик.

### Доступ к панели

`GET /api/*` требует токен в заголовке `X-TGFarm-Token`. Токен создаётся при
первом запуске в `data/api_token` и подставляется в страницу на стороне
сервера. Зачем: браузер свободно ходит на `127.0.0.1`, поэтому без токена любая
открытая страница могла бы **форс-публиковать** пост. Кастомный заголовок не
подделывается кросс-сайтовой формой, а сама страница токен наружу не отдаёт
из-за same-origin policy. Токен в query string намеренно не принимается: URL может попасть
в историю браузера, referer или сторонние журналы. Для обычных API-запросов
используется заголовок; для медиаэлементов, которые не умеют задавать заголовки,
панель получает отдельную cookie с флагами HttpOnly и SameSite=Strict.

```bash
curl -H "X-TGFarm-Token: $(cat data/api_token)" localhost:8000/api/status
```

По умолчанию сервер слушает только `127.0.0.1`. `--host 0.0.0.0` — осознанное
решение, CLI предупредит об этом в лог.

### Дзен — вторая площадка, а не кросспост

`zen_misc_ru` («Всякая всячина») — канал с `platform: dzen` и `catch_all: true`.
S3 добавляет его детерминированным маршрутом к каждому кластеру, независимо от
ниши, и S4 пишет для него отдельный пост. Это не копия Telegram-поста: у Дзена
свой заголовок, тело и лимит 10 000 символов, поэтому S9 кросспостит только
Telegram-источники и никогда не отправляет в Дзен второй раз.

У Дзена нет публичного API публикации, поэтому S7 работает через веб-редактор:
Playwright открывает `dzen.ru/profile/editor` в отдельном Chrome-профиле,
печатает заголовок и текст с человекоподобными задержками. Если у поста есть
фотография из ленты или `og:image` статьи, S6 сохраняет её в `data/media` и S7
вставляет снимок в текст после вступления; без неё используется обложка.
Первый запуск — ручной вход:

```powershell
tgfarm dzen-login
```

Профиль сохраняется в `DZEN_PROFILE_DIR` (по умолчанию `data/dzen_profile`);
повторный вход нужен только когда истечёт сессия Яндекса. При капче автоматика
останавливается и просит пройти её вручную — обходить её код не пытается. Без
профиля live-публикация оставляет пост в `scheduled` с ошибкой и повтором через
60 минут; в dry-run пост помечается опубликованным, а remote id пишется в
`crosspost_logs`. Ссылка на публикацию появляется в карточке поста.

Метрики Дзена читаются из Studio (`publications-stat`): показы, открытия,
дочитывания, комментарии, реакции, репосты и подписчики. Они привязываются к
посту по ссылке из `crosspost_logs`, поэтому в отчёте появляются CTR
(`открытия / показы`) и дочитываемость (`дочитывания / открытия`). В live-режиме
сбор запускается после цикла не чаще раза в 30 минут; вручную — командой:

```powershell
tgfarm dzen-stats
```

Настройки: `DZEN_PUBLISHER_ID` (можно оставить пустым — id определится по
авторизованной странице), `DZEN_STATS_ENABLED`, `DZEN_STATS_INTERVAL_MIN`,
`DZEN_STATS_TIMEOUT_S`. Если метрик мало, веса углов и часов остаются прежними;
после накопления данных S3 сдвигает выбор угла, а отчёт — час слота, в сторону
лучшего качества (`CTR × дочитываемость`).

```yaml
# config/personas.yaml
- id: zen_misc_ru
  title: "Всякая всячина"
  niche: general
  platform: dzen
  catch_all: true
  posts_per_day: 8
  min_chars: 350
  max_chars: 2500
```

### Аккаунт Telegram — только на чтение

Бот видит ровно те каналы, где его добавили админом, и больше ничего. Отсюда три
пробела, которые закрывает сессия аккаунта: настоящий список каналов вместо
предположений из YAML, **живая статистика** постов (просмотры, реакции,
репосты) и каналы Telegram как источник контента.

```bash
# api_id и api_hash — с https://my.telegram.org → API development tools
tgfarm telegram login     # код из Telegram + пароль 2FA
tgfarm telegram chats     # все каналы и группы, которые видит аккаунт
tgfarm telegram sync      # сверить каналы из YAML с реальностью
tgfarm telegram stats     # забрать реальные просмотры и реакции
tgfarm telegram status    # что подключено
tgfarm telegram logout    # стереть сессию
```

**Почему только чтение.** Файл сессии — это не логин, это сам аккаунт. Публикация
остаётся на боте: бан бота стоит бота, бан аккаунта стоит канала и подписчиков.
Запрет не декларативный — `ReadOnlyClient` блокирует 30 изменяющих методов
(`send_message`, `join_channel`, `delete_account`, …) по имени при обращении, так
что до отправки запроса дело не доходит.

Сверка каналов (`sync`) показывает расхождения, а не просто обновляет числа:

```json
{
  "matched": 7,
  "missing_in_telegram": [{"id": "city_local_ru", "title": "..."}],
  "bot_not_admin": [{"id": "health_evidence_ru", "reason": "бот не администратор"}],
  "unconfigured_channels": [{"id": 999, "title": "...", "participants": 128000}]
}
```

### Источники: что добавлено

Всего 251 источник; в конфиге восемь типов коллекторов, девятый (`rss` для
статических лент) добавляется одной записью:

| Тип | Что это | Ключ нужен |
|---|---|---|
| `rss` | Обычные RSS/Atom ленты | нет |
| `gnews` | Google News по запросу | нет |
| `gdelt` | GDELT DOC API, 65 языков | нет |
| `reddit` | Сабреддиты через `.rss` | нет |
| `hackernews` | hnrss.org, фронт-страница и запросы | нет |
| `github` | Релизы репозитория (`.atom`) | нет |
| `youtube` | Лента видео канала | нет |
| `telegram` | Каналы Telegram | сессия аккаунта |
| `websearch` | Новости по запросу | Tavily или Serper |

Reddit лимитирует по IP жёстче всех (примерно один запрос на 15–30 с), поэтому
по умолчанию включён один сабреддит, а второй помечен выключенным с объяснением
в `config/sources.yaml`.

Запросы к одному хосту сериализуются с паузой (`HostPacer`): без этого два
источника на одном сайте ловили 429 друг от друга.

### Редактор и предпросмотр

Любой пост, который ещё не отправлен (`draft`, `gated`, `scheduled`,
`rejected`), можно править прямо в панели. После правки гейты качества
**перезапускаются** — старый вердикт описывал другой текст, и оставить его было бы
враньём. Отсорванный слот не теряется: если текст прошёл проверки, запланированное
время сохраняется.

```bash
curl -X PUT localhost:8000/api/posts/<id>/draft \
  -H "X-TGFarm-Token: $(cat data/api_token)" \
  -H 'Content-Type: application/json' \
  -d '{"hook":"...","body":"..."}'
```

Предпросмотр рендерит пост так, как его покажет Telegram, вместе с обложкой и
счётчиком символов к лимиту в 4096.

### Адаптивные форматы (S10)

Формат выбирается по сигналам кластера, а не по вкусу: число изданий, объём
доступного текста, плотность чисел, наличие лицензированного видео.

| Формат | Когда | Бюджет |
|---|---|---|
| `flash` | один источник, короткий текст, высокий heat | 150–320 |
| `stat` | плотность чисел ≥ 1.1 на 100 символов | 200–420 |
| `news` | один источник с пригодным текстом | 400–700 |
| `analysis` | несколько изданий, от 2000 символов | 600–1100 |
| `article` | ≥ 4500 символов из ≥ 2 изданий | 1200–2500 |
| `video` | к источнику прикреплено разрешённое видео | 200–600 |

`fit_persona()` не даёт формату разойтись с каналом: персона с потолком в 600
символов понижается с `article` до `news`, а не получает длинный черновик,
который гейт длины отклонит. Статьи (1200–2500 символов) умеет публиковать
`tech_deep_ru` и `zen_misc_ru` — остальные Telegram-каналы по определению короче.

### Видео и лицензии (S11)

Видео включается флагом и проходит строгий фильтр:

* файл на **том же домене**, что и статья — издание предлагает его как часть
  собственного материала;
* либо на странице есть явная **Creative Commons / public-domain** пометка.

Отклоняются всегда: YouTube, TikTok, Vimeo, VK, Дзен, Rutube и прочие
платформы, а также любой чужой домен без лицензионной пометки. Отказы считаются
и показываются в панели (`GET /api/status` → `capabilities.video`), чтобы было
видно, во сколько обходится фильтр. `VIDEO_ALLOW_UNKNOWN=1` снимает правило
про чужой домен — это осознанный юридический риск, а не оптимизация.

Медиа из фида записывается на этапе S1 (`raw_items.media_links`,
`raw_items.media_kind`), иначе S11 пришлось бы заново качать ленту, чтобы
понять, что к новости было приложено. Если лента не приложила ничего, S11
загружает страницу статьи и смотрит `og:video` / `<video>`, но не чаще
`MAX_VIDEO_PROBES` раз на кластер.

### LLM: OpenCode Zen

`LLM_PROVIDERS` по умолчанию начинается с `opencode`: один ключ покрывает всю
ферму, и Zen отдаёт модели от Anthropic, OpenAI и Google через единый endpoint.
Ключ обязателен. `-free`-модели не помогают: их файр-тир отвечает
`403 "free tier can only be used from within OpenCode"`, а платные — `401` без
рабочего ключа. Поэтому без ключа провайдер **пропускается без единого запроса**
и цепочка сразу идёт дальше; `offline` стоит последним как гарантированный
откат.

```bash
LLM_PROVIDERS=opencode,anthropic,openai,ollama,offline
OPENCODE_ZEN_TOKEN=sk-...          # service account key из консоли OpenCode
OPENCODE_ZEN_MODEL=claude-sonnet-4-6
OPENCODE_ZEN_FREE_ONLY=false       # true — ограничиться -free моделями
```

Маршрутизация по имени модели совпадает с документацией Zen: `claude-*` и
`qwen*` → `/inference/anthropic/v1/messages`, `gpt-*` и `o*` →
`/inference/openai/v1/responses`, `gemini-*` →
`/inference/google/v1beta/models/<model>:generateContent`, остальные (kimi, glm,
minimax, free-модели) → `/inference/openai/v1/chat/completions`. Разбор ответа
покрывает все четыре формы, поэтому смена модели не требует правок кода.

### Любой OpenAI-совместимый провайдер

Gemini, Groq, OpenRouter, Together, Fireworks и локальный vLLM говорят на
одном протоколе. Провайдер `compatible` включается тремя строками в `.env`:

```bash
LLM_PROVIDERS=compatible,offline
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
LLM_API_KEY=...
LLM_MODEL=gemini-2.5-flash
```

Готовые base URL: Gemini `…/v1beta/openai`, Groq `https://api.groq.com/openai/v1`,
OpenRouter `https://openrouter.ai/api/v1` (бесплатные модели помечены `:free`),
Together `https://api.together.xyz/v1`, локальный vLLM
`http://127.0.0.1:8000/v1` — **ключ не нужен**, если адрес локальный.

Что умеет бесплатно на момент написания: у Gemini щедрый free-tier с лимитами,
у Groq и Mistral — бесплатные лимиты запросов, у OpenRouter — модели с суффиксом
`:free`, у GitHub Models — бесплатные квоты. Ollama локально вообще без
ключей и без сети.

Оговорка: ферма съедает сотни токенов на пост, поэтому «бесплатно» здесь скорее
про принцип, чем про экономию — но лимит запросов у free-tier'ов важнее цены,
и `compatible` позволяет переключиться между ними строкой в `.env`.

### LongCat

LongCat API совместим с OpenAI и подключается отдельным провайдером `longcat`:

```bash
LLM_PROVIDERS=longcat,offline
LONGCAT_API_KEY=ak_...
LONGCAT_MODEL=LongCat-2.5-Preview
LONGCAT_THINKING=false
```

Endpoint: `https://api.longcat.chat/openai/v1`. Платформа сейчас отдаёт только
`LongCat-2.5-Preview` и `LongCat-2.0`; обе модели платные (около $2/$8 за million
токенов), бесплатной модели в каталоге нет. `thinking=false` отключает скрытое
рассуждение и ускоряет ответ. JSON-режим работает через промпт, потому что
`response_format` нет в списке поддерживаемых параметров LongCat.

### Картинки

Pillow-шаблоны — основной путь: единый визуальный язык канала невозможно
удержать генеративной моделью на сотнях постов. AI-арт включается для части
постов, которые шаблон не вывозит.

OpenAI-совместимый провайдер:

```bash
IMAGE_ENABLED=true
IMAGE_PROVIDER=openai
IMAGE_BASE_URL=https://api.openai.com/v1
IMAGE_API_KEY=...
IMAGE_MODEL=gpt-image-1
```

Cloudflare Workers AI, бесплатный FLUX.1 [schnell]:

```bash
IMAGE_ENABLED=true
IMAGE_PROVIDER=cloudflare
CLOUDFLARE_ACCOUNT_ID=...
CLOUDFLARE_API_TOKEN=...
CLOUDFLARE_IMAGE_MODEL=@cf/black-forest-labs/flux-1-schnell
CLOUDFLARE_IMAGE_STEPS=4
```

Free-план Workers AI даёт 10 000 Neurons в сутки — примерно 150–170 обложек
1280×720 при четырёх шагах. Account ID нужен именно для REST-пути Workers AI:
`https://api.cloudflare.com/client/v4/accounts/<id>/ai/run/<model>`. Ответ
FLUX — base64 JPEG; файл сохраняется с `.jpg`, чтобы Dzen загрузил правильный
MIME-тип.

**У Zen нет моделей изображений** — его `/inference/v1/models` отдаёт только
текстовые. Провайдер никогда не падает вместо шаблона: ошибка логируется,
`ai_art()` возвращает `None`, рендер идёт по шаблону.

### Тепловой скоринг

```
heat = 0.35 * источник      # авторитет издания
     + 0.25 * скорость      # число разных изданий за 6 часов
     + 0.20 * свежесть      # exp(-часов / 4)
     + 0.10 * кросс-типы    # согласованность RSS / GoogleNews / GDELT
     + 0.10 * дефицит нишы  # насколько тема не закрыта нашими же каналами
```

Порог по умолчанию `0.68` (`HEAT_THRESHOLD`); в текущем `.env` стоит `0.55`,
чтобы поток был плотнее. Ниже порога история копится в
кластере и ждёт роста, а не уходит в контент.

### Гейты качества

| Гейт | Что ловит |
|---|---|
| `structure` | Хук — не целое предложение / не 15–160 символов / >1 эмодзи |
| `length` | Выход за лимиты персоны. **Меряется редакционный текст** (хук + тело + CTA), а не полный пост: бюджет в 600 символов, включающий три URL, оставил бы ~200 символов прозы |
| `vocabulary` | Запрещённые слова персоны (`революция`, `100%`, `гарантированно`…) |
| `links` | Нет источников / больше `max_sources` / домен в блоклисте / битый URL |
| `copyright` | Тело целиком повторяет заголовок источника и не добавляет слов |
| `facts` | <50% утверждений подтверждены источником |
| `disclaimer` | В регулируемых нишах (здоровье, крипто) отсутствует обязательная оговорка |
| `redundancy` | Тело дословно повторяет хук (совпадение 6-словного n-грамма) |
| `uniqueness` | Пост слишком похож на собственные последние 200 |
| `tone` | LLM-критик 0–10, порог 7 |

Каждый провал даёт одной целевой рерайт с указанием причины. Два провала — отклонение.
Отклонение — это фича: ферма, которая публикует 60% черновиков, выдаёт лучший
контент, чем ферма, публикующая 100%.

### Расписание

Два режима в `config/slots.yaml`:

* `cadence.mode: weights` — часы и дни недели из измеренного распределения
  публикаций в Telegram (пик **17:00–18:00 МСК**), с джиттером внутри часа;
* `cadence.mode: interval` — непрерывный режим: пауза между постами одного
  канала считается от дневной квоты персоны, чтобы она растянулась на сутки.
  Так Дзен идёт с шагом ~12 минут (площадка не даёт чаще одного поста в
  10 минут), ВК — ~30 минут (потолок ~50 постов в сутки), а в сумме получается
  пост каждые 5–10 минут без flood control.

`fleet_posts_per_hour` остаётся верхней границей на весь парк в режиме `weights`
и не даёт каналам ударить одновременно.

### Что ферма никогда не делает

Закодировано в `tgfarm/s9_growth/__init__.py`, а не только в документации:

```python
FORBIDDEN_GROWTH_PRIMITIVES = frozenset({
    "mass_invite", "scrape_members", "unsolicited_dm", "auto_comment",
    "auto_react_from_owned_accounts", "buy_subscribers", "fake_reactions",
    "userbot_posting",
})
```

Любая попытка зарегистрировать такой примитив поднимает `UnsafeGrowthPrimitive`.
Причины не моральные: это спам по Пользовательскому соглашению Telegram, он даёт
перманентные баны, и по замерам он хуже легальных методов. Подробности и цифры —
в `RUNBOOK.md`, раздел «Почему нет комментинга».

Ферма также не скачивает видео с видеоплатформ и не перепечатывает чужие
материалы: у S11 есть лицензионный гейт, и он отказывает по умолчанию.

## Конфигурация

Всё, что настраивается, лежит в YAML — перенастройка фермы не требует правки кода.

```yaml
# config/personas.yaml
- id: ai_tech_ru
  title: "AI & Tech — разбор без хайпа"
  niche: tech
  platform: telegram
  language: ru
  posts_per_day: 3
  tone: [factual, no_hype, specific, neutral]
  banned_words: [революция, взрывной, 100%, гарантированно]
  min_chars: 150
  max_chars: 600
  palette: {bg: "#0B1020", fg: "#E8ECF8", accent: "#4C8DFF"}
  disclaimer: null
```

```yaml
# config/sources.yaml
- id: gnews_tech_ru
  kind: gnews
  url: "https://news.google.com/rss/search?q={{Q}}&hl=ru&gl=RU&ceid=RU:ru"
  params: {Q: "искусственный интеллект (публикация: когда-14д)"}
  niches: [tech, software]
  weight: 0.62
```

**Парсинг Telegram исключён намеренно.** API Terms прямо запрещают использовать
данные платформы для обучения и развития ИИ-систем, а массовый сбор -> бан.
Сырьё берётся из первичных публичных источников.

Готовые ниши (8 штук) в `config/personas.yaml`: AI/tech, бизнес-финансы,
крипто-аналитика, нейросервисы, наука, доказательная медицина, локальный город,
узбекский tech. Плюс `zen_misc_ru` — общий канал в Дзене без ниши.

### Импорт старых публикаций в память

Экспорт Telegram Desktop в JSON, ответ VK wall API в JSON или универсальный JSON/CSV
можно добавить в архив, чтобы поиск и досье тем видели публикации, сделанные до запуска
TgFarm. Нужен существующий ID канала из `tgfarm channels`.

```bash
tgfarm history-import export.json --channel my_channel
# Если предпросмотр корректен, явно подтвердите запись:
tgfarm history-import export.json --channel my_channel --platform telegram --apply
```

Без `--apply` команда ничего не записывает. Повторный запуск безопасен: импорт отсекает дубликаты по ID и тексту. Импорт сохраняет исходную дату и ссылку,
помечает записи как исторические, пропускает точные дубликаты и **не публикует** их
повторно. Для CSV ожидаются колонки вроде `platform,external_id,published_at,title,text,url`.
Для универсального JSON подойдут список объектов или объект с `posts`/`items`, где есть
поля `text`/`body` и дата. История Дзена зависит от доступного экспорта, поэтому подойдёт
его CSV или JSON с теми же полями, если такой экспорт был получен отдельно.

## Резервные копии и восстановление

Перед первым большим импортом выполни `tgfarm backup` и проверь поля `verified` и `integrity_check`. Команды `history-import ... --apply` и `history-import-telegram ... --apply` делают этот шаг автоматически и прекращают запись, если копию не удалось проверить. Для внешней БД настрой штатный backup и используй `--skip-preimport-backup` только после ручной проверки такой копии.

Встроенный scheduler создаёт проверенную SQLite-копию каждый день в 04:00 по `TZ`. При запуске ферма дополнительно проверяет последнюю успешную копию: если её нет, она старше `BACKUP_MAX_AGE_HOURS` (по умолчанию 36) или предыдущая попытка закончилась ошибкой, ферма пробует создать копию сразу. Каждый новый snapshot проходит SQLite `integrity_check` и автоматическую пробную реставрацию во временную базу с проверкой схемы, количества строк и внешних ключей. Только после успешного restore-test разрешены ротация старых копий и копирование в зеркало. Старые копии ограничиваются настройкой `KEEP_BACKUPS`.

Для копии на отдельном диске или сетевом ресурсе укажи `BACKUP_MIRROR_DIR`. Зеркало проверяется отдельно, включая SHA-256. Если резервирование отсутствует или устарело, watchdog выставляет предупреждения `backup_missing` / `backup_stale`; неудача конкретной операции отмечается как `backup_failed`. Команда `tgfarm backup-test FILE` остаётся доступна для ручной проверки старых снимков и диагностики. Для внешней БД настрой штатный backup и проверяй его средствами самой СУБД.

Watchdog проверяет свободное место на файловых системах, где лежат данные фермы, резервные копии и настроенное зеркало. По умолчанию ниже 10 ГиБ создаётся предупреждение `disk_space_low`, ниже 3 ГиБ критический сигнал `disk_space_critical`. Если несколько каталогов находятся на одном диске, диск проверяется один раз; реальные пути не выводятся в сообщениях. Пороги настраиваются через `DISK_FREE_WARN_GB` и `DISK_FREE_CRITICAL_GB`; значение `0` отключает соответствующий порог.

Watchdog также отслеживает состояние включённых новостных источников: после нескольких подряд ошибок отдельные источники отмечаются как деградировавшие, а если все включённые источники ушли в повторные ошибки/cooldown, создаётся критический сигнал `source_fleet_down`. Сигнал содержит только количество источников, а не их URL или текст ошибок.

Отдельно контролируется свежесть самого опроса источников: каждый включённый источник должен обновлять `last_fetched_at` с учётом фактического интервала опроса (`min_interval_s` и адаптивный backoff, если он включён; допуск: минимум 2 часа или три эффективных интервала). Частичное отставание создаёт `source_collection_degraded`, полный застой всех включённых источников — `source_collection_stale`. Это отличает «источник ничего нового не нашёл» от «ферма давно не опрашивала источники».

Watchdog также следит за ростом очередей в live-режиме: `scheduled_queue_backlog` предупреждает о слишком большой очереди публикации и повышает уровень до error при двукратном превышении порога; `editorial_review_backlog` показывает накопление черновиков, ожидающих одобрения. Пороги настраиваются через `QUEUE_BACKLOG_ALERT_THRESHOLD` (100) и `EDITORIAL_BACKLOG_ALERT_THRESHOLD` (50). В offline-режиме эти алерты отключены.

Доставка самих Telegram-уведомлений тоже журналируется. Если API Telegram отвечает ошибкой или сеть недоступна, ферма записывает безопасное состояние `alert_delivery` и показывает `alert_delivery_failed` в панели; сырые тела ответов, токены и тексты исключений не публикуются. После успешной следующей попытки сигнал снимается.

Подключения площадок с поддерживаемой read-only проверкой дополнительно проверяются при старте и затем каждые 6 часов, если площадка включена и её настройки заполнены. Это не публикует посты: проверяются только профиль/доступ API. Отказ в доступе поднимает `platform_auth_failed`; временный сетевой сбой остаётся неопределённым результатом, а режим `TGFARM_MODE=off` полностью отключает сетевые проверки.
Карточки площадок показывают время последней подтверждённой проверки авторизации, чтобы можно было отличить актуальный статус от старой записи.

Недельный отчёт по воскресеньям включает не только публикации и просмотры, но и до трёх рекомендаций по формату, углу подачи или стилю захода из portfolio analytics. В дайджест попадают только рекомендации, прошедшие пороги зрелости и выборки; если данных мало, ферма так и пишет. Эти выводы не меняют настройки автоматически.
 
Подробный [порядок безопасного smoke-теста](docs/SMOKE_TEST_VK_DZEN.md) описывает отдельно offline-проверки и реальные публикации.

## Разработка

```bash
pytest tests -q          # regression suite, без сети и ключей
ruff check tgfarm tests
python -m tgfarm.cli demo
```

### Решения, которые стоит знать

**Синхронный SQLAlchemy, а не async.** Нагрузка — десятки записей в минуту.
Синхронный код тривиально отлаживается; блокирующие вызовы уходят в поток через
`core.run.to_thread`.

**Векторы в numpy, не в pgvector.** Рабочий набор — недели данных (50–200 тыс.
векторов). Матричное умножение отвечает за top-k быстрее, чем round-trip в
расширение, и убирает сервис из стека. `sync_from_db` перестраивает индекс при
старте; миграция на pgvector — точечная правка `db/vector.py`.

**Эмбеддинги по умолчанию локальные.** Signed hashing trick по символьным
4-граммам: без ключа, без загрузки модели, детерминированно. Для двух задач фермы
(поиск дублей и «мы это уже говорили») этого достаточно. `EMBEDDING_PROVIDER=openai`
переключает на семантику без единой правки в коде.

**Офлайн-композер — не заглушка.** Если LLM недоступен, конвейер собирает валидный
пост с источниками из кластера. Ферма не встаёт из-за лимита API.

**Симуляшки — 62 бита.** SQLite `INTEGER` знаковый; 64-битный simhash переполняет
колонку при вставке. Порог 12 откалиброван на реальных заголовках: два варианта
одной новости дают 7–13 бит, несвязанные темы — 17–30.

**Точность фактчека — общая нормализация чисел.** Токен и хаслог проходят
идентичный трансформ, иначе `5.5` никогда не найдёт `5.5` внутри `GPT-5.5`.
Запятая приводится к точке (RU/EU источники пишут `0,02`).

**Стем-пересечение вместо точного.** Точное множественное пересечение со
словарём ключевых слов даёт ~0 на реальном русском: `ставку` не равно `ставк`.
Сопоставление по префиксу — обязательный минимум для неанглийских ниш.

Инфраструктура без рекламы — это себестоимость производства. Реклама — это
стоимость роста, и она на порядок выше.

Панель «Использование ИИ» показывает расход дневного лимита в **онлайн-вызовах**, офлайн-фолбэки, задержку и резервы, не завершённые более 15 минут. Это не денежный биллинг: реальные суммы и цены токенов нужно сверять с кабинетом конкретного провайдера. API отчёта: `GET /api/ai/usage?days=7` (от 1 до 30 дней).
Watchdog отдельно предупреждает при достижении 80% `AI_DAILY_BUDGET` (`ai_daily_budget_near_limit`) и при исчерпании лимита (`ai_daily_budget_exhausted`). Сигнал не создаётся для пустой/офлайн-установки без зарезервированных онлайн-вызовов; после исчерпания доступные офлайн-сценарии продолжают работать.
Резервирование дневного лимита атомарно сериализуется в SQLite и PostgreSQL, поэтому параллельные worker-процессы не должны одновременно занять один и тот же последний слот. Незавершённые резервы учитываются консервативно до восстановления/разбора результата, чтобы авария не открывала скрытый перерасход.

Подробный разбор ниш, рынка и юнит-экономики: `TG-CHANNEL-FARM.md`.
Эксплуатация и аварийные процедуры: `RUNBOOK.md`.
